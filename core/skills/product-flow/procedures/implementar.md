# implementar (ciclo fijado por el usuario, paso 13)

Antes de tocar código a ciegas, **siempre** este orden:

1. **Escanear** — leer el código/docs relevantes (qué hay hoy, qué toca la tarea).  
2. **Planificar** — proponer cambios concretos (archivos, enfoque); puerta humana si el plan es de producto/riesgo.  
3. **Evaluar** — contrastar el plan con requisito, tests y riesgos (¿rompe algo? ¿falta evidencia?).  
4. **Reemplazar / aplicar** — hacer el cambio mínimo acordado.  
5. Luego: `presentar` → `evidenciar` → `verificar` (no marcar hecha sin evidencia).

## Límites

- Una sola `TASK` en `preparada` / `en_curso` por ciclo.  
- Sin resets destructivos ni borrar trabajo del usuario.  
- No digas “verificada” desde implementar: usa el flujo de verificación.
